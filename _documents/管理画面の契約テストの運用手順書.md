# 管理画面の契約テストの運用手順書

Core の C1〜C5 を、Q の本体の起動コード・HTTP パイプラインと SQLite で実行する（Issue #708）。
**Core preview.11 の公開と、C2 の応答の判断を待つ Draft。通常の CI ではまだ新しい試験を実行しない。**

## 構成

`tests/VehicleVision.PleasanterTools.Questionnaire.Integration.Tests/` に次を置く。

| ファイル | 役割 |
|---|---|
| `AdminContractTests.cs` | Core の `AdminAuthenticationContractTests` を継承し、ホストの生成だけを実装する |
| `AdminContractHost.cs` | `IAdminContractHost`。`WebApplicationFactory<Program>`、専用 DB・鍵・cookie 容器、準備用ヘルパと HTTP の設定 |

- 全入口を「有る」と宣言する。`/api/admin`、cookie 名、要求本文と応答の項目名は Q 側だけが知る
- DB は試験ごとに `temp/20261022_contract-tests/<一意な ID>/` へ作り、終了時に破棄する。
  SQL Server を使う既存 E2E の DB や管理者は消さない
- 本体のマイグレーションを先に適用し、起動時には未適用がないかを検査する。
  送信ワーカーは外すが、認証・認可・セッション・管理 API・ストアは本体を使う
- 利用者・TOTP の準備はストア経由。ログインと検証対象の操作は HTTP 経由。
  `TotpService` は時計を注入できないため、未使用の時間枠で登録して実時刻の数字を作る
- 本体コードは変更しない。契約違反を見つけてもホストの応答変換や認証の偽物で通さない

根拠は `AdminContractTests.cs:6-9`、`AdminContractHost.cs:59,181`、
同ディレクトリの `.csproj:21-25`（2026-10-22）。

## 公開前のローカル検証

未公開版の `PackageReference` をコミットしないため、
`EnableAdminContractTests=true` を渡したときだけ新しい 2 ファイルをコンパイルする。
**一時参照なしで有効化すればビルドが失敗する。黙って試験を成功扱いにはしない。**

1. Core の試験用パッケージをローカルで pack し、一時 NuGet フィードから参照する。
   または試験プロジェクトに Core.Web.Testing への一時 `ProjectReference` を置く
2. 次を実行する（リポジトリのルートから）
3. 一時参照とフィード設定を取り除く。コミットしない

```bash
dotnet test tests/VehicleVision.PleasanterTools.Questionnaire.Integration.Tests \
  -c Release -p:EnableAdminContractTests=true \
  --filter FullyQualifiedName~AdminContractTests
```

`QUESTIONNAIRE_INTEGRATION=1` は不要。Pleasanter・SQL Server に接続しない。
Windows の Code Integrity に実行を拒まれる場合だけ、短い専用パスへ複製して実行し、複製を削除する。

## 公開後の切り替え

Core `VehicleVision.PleasanterTools.Core.Web.Testing` の `0.1.0-preview.11` 公開を確認してから行う。

1. 試験プロジェクトに正式な `PackageReference` を追加する（本体プロジェクトには追加しない）
2. `.csproj` の `EnableAdminContractTests` によるコンパイル除外を削除する
3. NOTICE に Core の版とデュアルライセンスを記録する（既存の Core パッケージと同じ扱い）
4. 通常のビルドと契約テストを再実行する。C2 の判断が済み、全契約が通るまで Draft を解除・マージしない

## 2026-10-22 の結果

基点: Q `004766d`。16 件中 **15 成功・1 失敗**、スキップなし。
一時的な `ProjectReference` と、ローカルで pack した NuGet の参照の両方で同じ結果になった。

| 契約 | 結果 |
|---|---|
| C1 | 2 件成功。登録済みの `/enroll/*` は 403、元の TOTP でログイン可能 |
| C2 | 3 件成功・1 件失敗。未指定と誤りは 401、正解は 200 と Reenroll cookie。5 回目に 423 は満たさない |
| C3 | 6 件成功。Reenroll と Pending の混同・cookie 名の付け替えを拒む |
| C4 | 3 件成功。Pending の管理操作は 401 |
| C5 | 1 件成功。失敗理由によらず 401 と同じ本文 |

**C2 は実装と契約の不一致。** 実際は 5 回すべて 401、続く正しいパスワードは 423。
締め出し自体は作動しており、無制限に試せるという結果ではない。
`src/VehicleVision.PleasanterTools.Questionnaire.Web/Services/AdminAuthenticator.cs:152-165,452-465`
で、回数を記録した後に `Invalid` を返しているため。

選択肢は、別の変更で 5 回目に 423 を返すよう修正するか、
共通契約を「5 回で締め出し、次の要求から 423」へ決め直すこと。
今回はどちらも選ばず、本体・契約を変えない。

SQL Server・Pleasanter 実機・Redis・cookie 属性・キャッシュ・監査内容・時計の固定は未確認。
既存の実機 E2E 全体が通ったという結果ではない。
