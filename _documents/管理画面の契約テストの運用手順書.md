## 構成

`tests/VehicleVision.PleasanterTools.Questionnaire.Integration.Tests/` に次を置く。

| ファイル | 役割 |
|---|---|
| `AdminContractTests.cs` | Core の `AdminAuthenticationContractTests` を継承し、ホストの生成だけを実装する |
| `AdminContractHost.cs` | `IAdminContractHost`。`WebApplicationFactory<Program>`、専用 DB・鍵・cookie 容器、準備用ヘルパと HTTP の設定 |

- 全入口を「有る」と宣言する。`/api/admin`、cookie 名、要求本文と応答の項目名は Q 側だけが知る
- DB は試験ごとに `temp/20261022_contract-tests/<一意な ID>/` へ作り、終了時に破棄する。
  SQL Server を使う既存 E2E の DB や管理者は消さない
- 本体のマイグレーションを先に適用し、起動時には未適用がないかを検査する。
  送信ワーカーは外すが、認証・認可・セッション・管理 API・ストアは本体を使う
- 利用者・TOTP の準備はストア経由。ログインと検証対象の操作は HTTP 経由。
  `TotpService` は時計を注入できないため、未使用の時間枠で登録して実時刻の数字を作る
- 本体コードは変更しない。契約違反を見つけてもホストの応答変換や認証の偽物で通さない

根拠は `AdminContractTests.cs:6-9`、`AdminContractHost.cs:59-84,181-201`、
同ディレクトリの `.csproj:17`（2026-10-22）。

## ローカル検証

リポジトリのルートから実行する。

```bash
dotnet restore VehicleVision.PleasanterTools.Questionnaire.slnx
dotnet build VehicleVision.PleasanterTools.Questionnaire.slnx --no-restore -c Release
dotnet test tests/VehicleVision.PleasanterTools.Questionnaire.Integration.Tests \
  --no-build -c Release \
  --filter FullyQualifiedName~AdminContractTests
```

`QUESTIONNAIRE_INTEGRATION=1` は不要。Pleasanter・SQL Server に接続しない。
Windows の Code Integrity に実行を拒まれる場合だけ、短い専用パスへ複製して実行し、複製を削除する。

公開前に同じ版番号で pack したパッケージが NuGet キャッシュにある場合は、
通常の復元だけでは公開版に置き換わらない。
その場合は worktree 内の専用キャッシュへ nuget.org から復元してから、
上のビルドに `-t:Rebuild` を付けて実行する。検証後、専用キャッシュを削除する。
共有の NuGet キャッシュを消したり、ローカルフィードの設定をコミットしたりしない。

```bash
dotnet restore VehicleVision.PleasanterTools.Questionnaire.slnx \
  --packages temp/20261022_contract-tests-validation/nuget-public \
  --source https://api.nuget.org/v3/index.json --no-http-cache
```

## 通常の CI

`.github/workflows/ci.yml` の既存 `build-test` ジョブで、単体テストの後に
`FullyQualifiedName~AdminContractTests` を指定して C1〜C5 の 16 件を実行する。
結果は `admin-contracts.trx` として既存のテスト結果 artifact に保存する。

外部 DB や Pleasanter の不要な SQLite 試験なので、SQL Server 前提の E2E や
4 DB の起動を待つ結合テストではなく、通常の push / PR で動くこのジョブへ載せる。
`QUESTIONNAIRE_INTEGRATION` を設定しないと素通りする既存の結合テスト全体は混ぜない。
`.github/workflows/integration.yml` の既存フィルタには
`FullyQualifiedName!~AdminContractTests` を追加し、重複実行を避ける。
E2E の既存フィルタは契約テストに一致しないため変更しない。

契約テストの成功だけで Draft を解除・マージしない。

### 公開前の C2 記録と、最初のローカル再実行の訂正

公開前の一時参照では「5 回目に 423」を期待して 15 成功・1 失敗だった。
今回も最初は同じ失敗を再現したが、キャッシュ内の未公開ビルドを使った結果であり、
公開版の試験結果ではなかった。パッケージの SHA-512 も公開版とは異なっていた。

公開版の `AdminAuthenticationContractTests.cs:82-107` は、
5 回の誤ったパスワードでの 401 と、続く正しいパスワードでの 423 を検証する。
専用キャッシュで公開版を復元した後は、ローカルでも CI と同じ全件成功になった。
**公開版では C2 の不一致・判断待ちは解消している。**
Q 本体・ホスト・共通契約には今回変更を加えていない。

契約試験自体の対象は SQLite の HTTP パイプラインであり、
SQL Server・Pleasanter 実機・Redis・cookie 属性・キャッシュ・監査内容・時計の固定は確認範囲外。
既存の SQL Server E2E は CI で成功したが、ローカルで E2E 全体を実行した結果ではない。
