# 開発環境

**ホストに .NET SDK も node も DB クライアントも入れずに動かせる**ことを目指している。
Pleasanter・3 種類の RDBMS・本アプリを Docker でまとめて起動する。

## 起動の順番

```bash
# 1. 検証環境（Pleasanter ＋ SQL Server ＋ 本アプリ）
docker compose --profile sqlserver up -d --wait

# 2. 動いているか見る
./scripts/smoke.sh
```

| 使うもの | 場所 |
|---|---|
| 回答画面 | <http://localhost:8081/f/{publicId}> |
| 管理画面 | <http://localhost:8081/admin> |
| Pleasanter | <http://localhost:8080> |
| SQL Server | `localhost,11433` |
| PostgreSQL | `localhost:15432` |
| MySQL | `localhost:13306` |

DB を替えるときはプロファイルを替える（`postgres` / `mysql`）。

## VS Code から

`.vscode` に一式入れてある。**コマンドを覚えなくても回せる。**

### タスク（`Ctrl+Shift+P` → `Tasks: Run Task`）

| タスク | 用途 |
|---|---|
| ビルド | ソリューション全体（`Ctrl+Shift+B` の既定） |
| テスト（単体） | 結合テストを除く |
| テスト（結合・3 RDBMS） | **検証環境を起動しておくこと** |
| テスト（結合・ウイルススキャンあり） | **clamav プロファイルで起動しておくこと** |
| テスト（このファイル） | 開いているテストクラスだけ |
| フロントエンド: 型検査 / ビルド / 開発サーバ | `npm run check` / `build` / `dev` |
| 検証環境を起動（SQL Server / PostgreSQL / MySQL） | プロファイルごと |
| 検証環境をアプリだけ作り直す | コードを変えた後。**DB は残る** |
| smoke | 配信・セキュリティヘッダ・管理画面の入口 |
| ライセンス検査 | **Pleasanter 本体への参照が混ざっていないか** |
| 秘密の鍵を作る | `QUESTIONNAIRE_SECRET_KEY` の値 |

### デバッグ（`F5`）

- **アプリ（SQL Server の検証環境へ繋ぐ）** — アプリだけ手元で動かし、DB と
  Pleasanter は Docker 側へ繋ぐ。**環境変数は `launch.json` に入っている**
- **結合テストをデバッグ** — `QUESTIONNAIRE_INTEGRATION=1` を渡して起こす
- **アプリ ＋ 管理画面** — アプリを起こしてブラウザで `/admin` を開く

**手元のアプリ（5067 番）と Docker のアプリ（8081 番）は別物。**
両方動かしても構わないが、**同じ DB を見ている**ので混ぜて試すときは注意する。

## 環境変数

`launch.json` と `compose.yaml` に入っているのは**検証環境用の固定値だけ**。
実値の与え方は [`App_Data/Parameters/README.md`](../App_Data/Parameters/README.md)。

| 変数 | 備考 |
|---|---|
| `QUESTIONNAIRE_DB_PROVIDER` | `SqlServer` / `PostgreSql` / `MySql` |
| `QUESTIONNAIRE_DB_CONNECTIONSTRING` | 本アプリの DB |
| `QUESTIONNAIRE_PLEASANTER_BASEURL` / `_APIKEY` / `_TIMEZONE` | 接続先 Pleasanter |
| `QUESTIONNAIRE_SECRET_KEY` | **失うと登録済みの 2 要素が全部使えなくなる** |
| `QUESTIONNAIRE_REQUESTS_PER_MIN` | 既定 60。**検証環境だけ緩める** |
| `QUESTIONNAIRE_LOGIN_ATTEMPTS_PER_5MIN` | 既定 10。**検証環境だけ緩める** |

**本番で緩めないこと。** 緩めた枠は総当たりの余地になる。

## 結合テストの注意

- **`QUESTIONNAIRE_INTEGRATION=1` を付けたときだけ中身が走る。**
  付けないと、テストは通ったように見えて何も確かめていない
- **DB を共有しているので並列にしない。** 互いの行を消し合う
  （`[assembly: CollectionBehavior(DisableTestParallelization = true)]`）
- **端から端まで通す試験は 1 件ごとに管理者を作り直す。**
  試験が増えるとレート制限の枠を使い切るので、検証環境では緩めてある

## `_reference` について

**Pleasanter 本体（AGPL v3）のサブモジュール。事実確認のための参照専用で、
コードの取り込みは禁止**（[`LICENSING.md`](../LICENSING.md)）。

VS Code の検索対象からは外してある。**うっかり写さないため。**
読みたいときは明示的に開くこと。
