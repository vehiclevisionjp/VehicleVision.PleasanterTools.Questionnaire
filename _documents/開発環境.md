# 開発環境

**ホストに .NET SDK も node も DB クライアントも入れずに動かせる**ことを目指している。
Pleasanter・3 種類の RDBMS・本アプリを Docker でまとめて起動する。

## 起動の順番

```bash
# 1. 検証環境（Pleasanter ＋ SQL Server ＋ 本アプリ）
docker compose --profile sqlserver up -d --wait

# 2. 動いているか見る
./scripts/smoke.sh
```

**マイグレーションは `up` の中で当たる。** `migrate` が先に走り、
アプリはその完了を待ってから立ち上がる。手で当てる必要はない。

### SQL Server だけ、DB を作る係が要る

**SQL Server のイメージには「起動時にこのデータベースを作る」仕掛けが無い**（Issue #97）。
接続文字列に書いても作られず、**スキーマの適用（FluentMigrator）もデータベース自体は
作らない。** 誰も作らなければ `migrate` が次で必ず落ちる。

```text
DB へ繋がらないまま 180 秒が過ぎた: Cannot open database "Questionnaire" requested by the login.
```

そこで `sqlserver` プロファイルにだけ `db-init` を置いてある。
**PostgreSQL と MySQL には要らない**（公式イメージの `POSTGRES_DB` /
`MYSQL_DATABASE` が起動時に作る）。CI も同じことをしている
（[`integration.yml`](../.github/workflows/integration.yml)）。

⚠️ **`db-init` にはプロファイルを付けていない。** `migrate` は 3 つの
プロファイルで共用しており、SQL Server 専用にすると
`service "migrate" depends on undefined service "db-init"` で
PostgreSQL / MySQL 側が壊れる（実測）。**`db` 自体が常に起動する作り**なので、
この係も常に走らせている。することは空のデータベースを 1 つ作るだけ。

## マイグレーション

**アプリの起動時には自動で当たらない**（[`データモデル設計.md`](データモデル設計.md) 5 章。
スケールアウトすると同時に走り得るため）。**代わりに、当てる係を別に立ててある。**

```bash
# 当てる（compose 経由。DB が起きるまで待つ）
docker compose --profile app run --rm --no-deps migrate --migrate --wait-for-db=180

# 当てずに、足りていないものを並べるだけ
docker compose --profile app run --rm --no-deps migrate --migrate-status
```

**アプリ本体と同じ実行ファイルの口。** 本番でも同じものを使う。

```bash
dotnet VehicleVision.PleasanterTools.Questionnaire.Web.dll --migrate
```

| 合図 | すること | 終了コード |
|---|---|---|
| `--migrate` | 足りていないものを当てる | 当たれば 0 |
| `--migrate-status` | 並べるだけ。**当てない** | 足りていれば 0、足りなければ 1 |
| `--wait-for-db=<秒>` | DB が接続を受けるまで待つ。**既定は待たない** | — |

**スキーマが古いままではアプリが起動しない。** 何が足りないかを並べて止まる。
列が無いまま動くと `Invalid column name` としか出ず、原因が分からないため
（Issue #32。結合テストが 21 件落ちた）。

検査を外したいときだけ `QUESTIONNAIRE_DB_SKIP_MIGRATION_CHECK=true` を設定する。
**本番で設定しないこと。** 古いスキーマのまま動き出す。

### マイグレーションを足したとき

**番号が他の作業ブランチと衝突していないか確かめること。**
FluentMigrator は**同じ番号を黙って読み飛ばす**（`MigrationNumberTests` が見張っている）。

| 使うもの | 場所 |
|---|---|
| 回答画面 | <http://localhost:8081/f/{publicId}> |
| 管理画面 | <http://localhost:8081/admin> |
| Pleasanter | <http://localhost:8080> |
| SQL Server | `localhost,11433` |
| PostgreSQL | `localhost:15432` |
| MySQL | `localhost:13306` |

DB を替えるときは**プロファイルと接続先の両方**を替える。
**プロファイルだけ替えても、アプリは SQL Server を見たままになる。**

```bash
DEV_DB_PROVIDER=PostgreSql DEV_DB_CONNECTIONSTRING='Host=db-postgres;Database=questionnaire;Username=postgres;Password=Questionnaire#Test1'   docker compose --profile postgres up -d --wait

DEV_DB_PROVIDER=MySql DEV_DB_CONNECTIONSTRING='Server=db-mysql;Database=questionnaire;Uid=root;Pwd=Questionnaire#Test1;AllowUserVariables=true'   docker compose --profile mysql up -d --wait
```

### デバッグ（`F5`）

- **アプリ（SQL Server の検証環境へ繋ぐ）** — アプリだけ手元で動かし、DB と
  Pleasanter は Docker 側へ繋ぐ。**環境変数は `launch.json` に入っている**
- **結合テストをデバッグ** — `QUESTIONNAIRE_INTEGRATION=1` を渡して起こす
- **アプリ ＋ 管理画面** — アプリを起こしてブラウザで `/admin` を開く

**手元のアプリ（5067 番）と Docker のアプリ（8081 番）は別物。**
両方動かしても構わないが、**同じ DB を見ている**ので混ぜて試すときは注意する。

## 環境変数

`launch.json` と `compose.yaml` に入っているのは**検証環境用の固定値だけ**。
実値の与え方は [`App_Data/Parameters/README.md`](../App_Data/Parameters/README.md)。

| 変数 | 備考 |
|---|---|
| `QUESTIONNAIRE_DB_PROVIDER` | `SqlServer` / `PostgreSql` / `MySql` |
| `QUESTIONNAIRE_DB_CONNECTIONSTRING` | 本アプリの DB |
| `QUESTIONNAIRE_PLEASANTER_BASEURL` / `_APIKEY` / `_TIMEZONE` | 接続先 Pleasanter |
| `QUESTIONNAIRE_SECRET_KEY` | **失うと登録済みの 2 要素が全部使えなくなる** |
| `QUESTIONNAIRE_REQUESTS_PER_MIN` | 既定 60。**検証環境だけ緩める** |
| `QUESTIONNAIRE_LOGIN_ATTEMPTS_PER_5MIN` | 既定 10。**検証環境だけ緩める** |
| `QUESTIONNAIRE_AUDITLOG_RETENTION_DAYS` | 管理操作の記録を残す日数。既定 365。**0 以下で消さない** |
| `QUESTIONNAIRE_ATTACHMENT_REJECTION_RETENTION_DAYS` | 添付を弾いた記録を残す日数。既定 90。**0 以下で消さない** |
| `QUESTIONNAIRE_NOTIFICATION_RETENTION_DAYS` | 管理者への知らせを残す日数。既定 90。**消えるのは既読だけ。0 以下で消さない** |
| `QUESTIONNAIRE_DEADLETTER_RETENTION_DAYS` | デッドレターを残す日数。**既定 0 ＝ 消さない。** ⚠️ **中身は回答そのもので、消すと戻らない** |
| `QUESTIONNAIRE_BACKLOG_PER_SURVEY` | 滞留で受付を止める件数（アンケート単位）。既定 10000。**0 以下で使わない** |
| `QUESTIONNAIRE_BACKLOG_TOTAL` | 滞留で受付を止める件数（全体）。既定 50000。**0 以下で使わない** |
| `QUESTIONNAIRE_SEND_PER_MINUTE` | 1 分あたりに送る件数の上限。既定 600。**0 以下で無制限** |
| `QUESTIONNAIRE_SCRIPT_TIMEOUT_MS` | 変換スクリプト 1 回あたりの実行時間の上限。既定 200。**上限は外せない** |
| `QUESTIONNAIRE_SCRIPT_MEMORY_BYTES` | 変換スクリプト 1 回あたりのメモリの上限。既定 4194304。**上限は外せない** |
| `QUESTIONNAIRE_SCRIPT_RECURSION_LIMIT` | 変換スクリプトの再帰の深さの上限。既定 64。**上限は外せない** |
| `QUESTIONNAIRE_EMBED_ALLOWEDHOSTS` | 埋め込みを許す配信元。読点区切り。**既定は空 ＝ 一切埋め込めない。** `www.example.com` はそのホストだけ、`*.example.net` はその下のホスト（`example.net` 自体は含まない）。[`非機能設計.md`](非機能設計.md) 1 章 |

**本番で緩めないこと。** 緩めた枠は総当たりの余地になる。

## 結合テストの注意

- **`QUESTIONNAIRE_INTEGRATION=1` を付けたときだけ中身が走る。**
  付けないと、テストは通ったように見えて何も確かめていない
- **DB を共有しているので並列にしない。** 互いの行を消し合う
  （`[assembly: CollectionBehavior(DisableTestParallelization = true)]`）
- **端から端まで通す試験は 1 件ごとに管理者を作り直す。**
  試験が増えるとレート制限の枠を使い切るので、検証環境では緩めてある

## `_reference` について

**Pleasanter 本体（AGPL v3）のサブモジュール。事実確認のための参照専用で、
コードの取り込みは禁止**（[`LICENSING.md`](../LICENSING.md)）。

VS Code の検索対象からは外してある。**うっかり写さないため。**
読みたいときは明示的に開くこと。

## HTTPS（自己署名）で動かす

**`crypto.subtle` は「安全なコンテキスト」（https か localhost）でしか使えない。**
検証環境は容器同士を平文の http で繋いでいるため、端から端まで通す試験では
proof-of-work の計算に**自前の SHA-256（控え）しか通っていなかった**（Issue #67）。
**本番で実際に使われる経路が一度も試されない**ので、8443 で https でも待ち受けるようにしてある。

| 使うもの | 場所 |
|---|---|
| 回答画面（平文） | <http://localhost:8081/f/{publicId}> |
| 回答画面（https） | <https://localhost:8443/f/{publicId}> |
| 管理画面（https） | <https://localhost:8443/admin> |

**平文の 8081 は今までどおり動く。** 平文でも回答できることは意図した仕様で
（控えの `Frontend/src/lib/sha256.ts`）、そちらの経路も試験で見張っている。

### 証明書の作られ方

**鍵はリポジトリへ置かない。** `docker compose up` のたびに `devcert` サービスが
容器の中で作り、名前付きボリューム `devcert` にだけ置く。
作業ツリーにもイメージの層にも残らない。

```bash
# 作り直したいとき（アプリも一緒に起こす）
docker compose --profile sqlserver up -d --wait

# 鍵ごと消す
docker compose --profile "*" down -v
```

- 作るのは `dotnet dev-certs https --export-path /https/aspnetapp.pfx --password <合言葉>`。
  **build 段階で既に引いている .NET SDK のイメージを使い回す**ので、依存は増えない
- 合言葉は `compose.yaml` の `x-devcert-password`（既定 `Questionnaire#DevCert1`）。
  **作る側と読む側で同じ値を使う。** `DEV_HTTPS_CERT_PASSWORD` で差し替えられる
- アプリ側は Kestrel の既定の証明書として読む
  （`ASPNETCORE_Kestrel__Certificates__Default__Path` / `__Password`）

**ブラウザは必ず警告を出す。** 自己署名であるうえ、この証明書が持つ名前は
`localhost` などに限られ、容器名の `questionnaire-app` とは一致しないため。
**検証環境だけの割り切りで、本番の設定には持ち込まないこと。**

### 平文が生き残る理由

`UseHsts` と `UseHttpsRedirection` は**開発環境では登録していない**
（`Program.cs`。`if (!app.Environment.IsDevelopment())` の中）。
検証環境は `ASPNETCORE_ENVIRONMENT=Development` なので、
**8443 を足しても 8080 が https へ飛ばされることはない。**

### 試験

`tools/screenshots/specs/secure-context.spec.ts` が、両方の経路をそれぞれの向きから見ている。

- https … `crypto.subtle.digest` が**実際に呼ばれ**、その解答がサーバに通ること
- 平文 … `crypto.subtle` が**無く**、それでも控えの解答がサーバに通ること

**「呼ばれた」は数えて確かめている。** `window.isSecureContext` を見るだけでは、
画面の側が本当にその道を通ったかは分からない。数える仕掛けは
`page.addInitScript` で外から包んでおり、**製品のコードには手を入れていない。**

証明書が自己署名なので、Playwright 側は `ignoreHTTPSErrors: true` で通している
（`tools/screenshots/playwright.config.ts`）。

```bash
docker compose --profile sqlserver up -d --wait
docker compose --profile sqlserver --profile screenshots run --rm screenshots
```
