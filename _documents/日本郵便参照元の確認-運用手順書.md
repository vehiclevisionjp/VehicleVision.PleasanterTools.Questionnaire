## 2. 確認できたこと（一次情報に記載あり）

| 事実 | 出典 |
| --- | --- |
| トークン取得は `POST /api/v2/j/token`。必須ヘッダーは `x-forwarded-for`（送信元 IP アドレス）と `User-Agent`。本文は `grant_type=client_credentials`・`client_id`・`secret_key`。応答は `scope`・`token_type=jwt`・`expires_in`・`token` | S1・S2 |
| 検索は「Authorizations: token」と表示されるのみで、ヘッダー名・形式（例: Bearer の有無）の記載はない | S1・S2 |
| `expires_in` の単位・期限切れの扱いの記載はない（例示は 123456 のみ） | S1・S2 |
| `count` の定義はない。例では `addresses` の要素数と一致（1 件の例で 1） | S1・S2 |
| `page` 既定 1、`limit` 既定・最大 1000。応答の `limit`・`page` は要求値の反映例 | S1・S2 |
| 404 は「Not Found」と表示されるのみで、発生条件の記載はない | S1・S2 |

### 5.1 質問文（案）

> 件名: 郵便番号・デジタルアドレス API（検索・トークン）の仕様について
>
> 貴社の「郵便番号・デジタルアドレス API」の利用を検討している、〔組織名〕の〔氏名〕です。
> 〔システムの概要: Web アンケートの住所入力で、回答者が入力した 7 桁の郵便番号を検索 API に送り、住所を補完する〕。
> API リファレンス（本番・テスト）を読みましたが、記載がなかった次の点を教えてください。
> 〔利用する API の版: ver1.0 / ver2.0 のどちらか〕。
>
> Q1. `GET /api/v2/searchcode/{search_code}` へ、トークンを付けるヘッダー名と形式（例: 接頭辞の有無）を教えてください。
>
> Q2. 組織・システム登録の手順と、必要な権限（組織管理者・API 管理者等）、システム登録で入力する項目、テスト用認証情報の入手方法を教えてください。
>
> Q3. 〔利用者が自組織の環境に導入するソフトウェアに API を組み込み、そのソフトウェアの提供元が別の組織である場合〕の、利用規約・第三者提供の特約の適用の考え方と必要な手続きを教えてください。
>
> Q4. レートリミットの数値と単位、超過時の応答、トークンの発行回数の上限、同じ資格情報で複数のサーバーから同時にトークンを取得した場合の扱いを教えてください。
>
> Q5. 検索応答の `count` は総件数ですか、そのページの件数ですか。
> `limit` を超える候補がある場合の `page` の扱い、
> 郵便番号に該当する住所が存在しない場合の応答（HTTP ステータスと本文）、7 桁未満（前方一致）の場合の `count` の意味を教えてください。

> Q6. トークン応答の `expires_in` の単位、有効期限の更新の推奨タイミング、期限切れ時の検索の応答、トークンの再利用・失効の扱いを教えてください。

> Q7. トークン取得の `x-forwarded-for` に指定すべき値（サーバーの外向き IP か）、登録した IP との照合の有無、複数の外向き IP・NAT がある場合の扱い、`User-Agent` の書式の制約を教えてください。

> Q8（任意）. 応答のサイズ・応答時間の目安、および、回答者へ郵便番号の外部送信を通知する際に、貴社として定めている文言や要件があれば教えてください。
